Brainstead doesn't have a model of its own. It runs the AI assistants' command-line tools installed on this computer, signed in with your own account, with the vault as their working folder. They read the vault directly and change it only through Brainstead's tools. Models you run yourself with Ollama count too: Codex runs them, pointed at Ollama instead of OpenAI.

## Choose the model for new chats
**New chats use** sets the model a new chat in [Ask](app:ask) starts with, and picking a model in a chat sets it too. Each chat keeps the model it started with. Background jobs use this model too, unless one has its own.

## Suggest a next message
With **Suggest a next message** on (on by default), after each answer in [Ask](app:ask) a model reads the last few exchanges and offers a follow-up in the message box; `→` types it in. It's one more call to the assistant per answer, using the model set for **Next-message suggestions in Ask** under Models by job.

## Changes
What assistants and runs change is made at once and listed in [Changes](app:review), where any of it can be reverted. **Keep the history of agent changes** sets how long: 90 days or 500 MB unless you change them, whichever comes first, and says how much space the history takes now. An assistant can read or set it too, when you ask. If your vault is in a OneDrive folder, older versions of a page are also in OneDrive's version history.

## Ingest
The **Meeting notes** and **Ingest** groups hold the switches about ingesting.

With **Ingest new sources as they arrive** on, an email or chat captured from the browser, or a file dropped or imported into Sources, is ingested straight away, as [Sources](app:sources) would. A Teams transcript isn't: it waits for its meeting note.

Under **Meeting notes**, **Ingest a meeting note once it's made** and **Then move the transcript to the Trash** (both on) are what happens after a note is written from a transcript. With both off, Brainstead asks after each note.

With **Also refresh pages whose sources changed** on, the daily check in [Settings › Jobs & schedule](app:settings/jobs) ingests again each source that changed since the pages citing it were written. What it finds is made at once, and a change that fails a check is held for you in [Changes](app:review).

## Give a job its own model
**Models by job** lets each kind of background work use a different model: **Daily and weekly summaries**, **Weekly review preparation** (the summaries' model unless it has its own), **Find tasks and projects**, **Ingest**, **Meeting notes from transcripts**, **Clarify suggestions**, **Contradiction checks**, **Triage, Draft reply and Doc check**, and **Next-message suggestions in Ask**. Click a job's button and pick a model. A job without one reads **Default** with the model it runs on in brackets: the model above, or for Weekly review preparation the summaries' when they have one of their own. The menu's **Default: the model new chats use** (or **Default: the summaries' model**) puts a job back to that. A job that can run on a schedule (the summaries, Weekly review preparation, Ingest, Meeting notes from transcripts and Contradiction checks) on an Ollama model, its own or one it follows, reads **Scheduled runs use … instead** under its name: the model its scheduled runs go on, at the job's effort where that model's assistant offers it.

Each job also has an **Effort** menu beside its model, with its assistant's levels (for an Ollama model, the thinking levels it names, and no menu if it names none). **Default**, the default, runs the job at its assistant's effort from Found on this computer. A level picked here is for that job only and never changes what a new chat starts with. Weekly review preparation uses the summaries' model but not their effort. Giving a job a model whose assistant lacks its level puts the job back to Default; when a model it only follows (**New chats use**, or the summaries') moves to such an assistant, it runs at Default until the model comes back. Picking a model in an [Ask](app:ask) chat changes **New chats use** too, so the jobs that follow it move with it; their effort settings stay as they are.

## See which assistants are installed
**Found on this computer** lists Claude Code, Codex, Antigravity, Copilot and Ollama, with each one's version, how many models it offers and where it is. If one is missing, **How to install** opens its install instructions in your browser. If one is installed but lists no models, open Terminal, run it and sign in. Click **Look again** after installing or signing in. An assistant can read this list, and look again, too.

**Ollama** is the models you run yourself on this computer. Codex runs them, pointed at Ollama's server, with its own agent loop, read-only sandbox, sessions and Brainstead's tools, so Codex must be installed too. The row shows Ollama's version and address, "Through Codex" with Codex's version, and the pulled models that can call tools (the others are named but not offered). It also says when Ollama isn't running or isn't installed (**How to install** opens ollama.com), when Codex is missing, and when no model is pulled yet (run `ollama pull <model>` in Terminal, then **Look again**). An Ollama model gets the text read from an image, not the picture. Ollama needs no account, and Codex runs it without your ChatGPT sign-in and with its plugins, apps, analytics and metrics off, so nothing goes to OpenAI. Brainstead uses Ollama only on this computer: if `OLLAMA_HOST` names another computer (anything but `localhost`, `127.0.0.1` or `::1`), the row says so, lists no models and offers no **How to install**, and a chat or run on an Ollama model stops with the same message. An Ollama model's **Effort** menu needs Ollama 0.34.3 or later, which reports each model's thinking levels; with an older one no menu shows and the model runs at its own default. Ollama runs in Ask and in runs you start by hand (**Run now**, a terminal session), never in scheduled jobs that write to the vault (the daily check, the scheduled summaries, a terminal call marked unattended): those go on **New chats use**, or Claude Code's Sonnet when that is an Ollama model too, and Brainstead's log (Settings › About) says so. Jobs you start by hand do best on a model of about 14B parameters or more (`gpt-oss:20b`, `qwen3:14b`); a smaller one misses things or makes them up.

## Set how hard an assistant thinks
Each installed assistant has an **Effort** menu on its row in **Found on this computer**: **Default** (the assistant chooses for each model), or **Low**, **Medium**, **High**, **Extra high** and **Max** (Codex stops at Extra high; Ollama at High). An Ollama model takes a level only if it names its thinking levels (gpt-oss: low, medium, high); for one that doesn't, the Effort menus in Ask and Models by job are hidden and it runs at its own default. More effort gives more careful answers, more slowly and using more of your plan. New chats in [Ask](app:ask) start with it, and background jobs run at it unless Models by job gives them their own. Not every model takes every level. Copilot's Auto model takes none, so the Effort menus in Ask and Models by job are hidden for it and it runs at its own default whatever is set here. Claude Code runs a missing level at the highest below it; for the others, a Codex model runs at the highest level below it that it takes, and a run that stops before answering with an error naming the effort runs once more at the model's own default. Brainstead's log (Settings › About) notes each fallback. Any other error stops the run and shows in the chat; pick a lower level then. An assistant can read or set the level when you ask.

## See which vault skills Brainstead now does itself
If the vault has Claude Code skills that Brainstead now does on its own screens, **Skills Brainstead does now** lists them and the screen each opens. Picking one in Ask's `/` list opens that screen. The vault's copies keep working in Claude Code until you retire them with **Retire them** under Moving over in [Settings › General](app:settings/general), which moves them to the Trash.

## Use Brainstead's tools from Terminal
**Brainstead's tools** shows, for each assistant found on this computer, the command that adds Brainstead's tools to it in a terminal (Terminal on a Mac, PowerShell or Windows Terminal on Windows), in every folder. On Windows the command points at the installed Brainstead.exe. **Copy** copies it; run it once for each assistant you use. One installed later shows here after **Look again**. In Ask, Claude Code, Codex and Copilot get the tools already; Antigravity reads with its own tools only. When an image is ingested, Claude Code and Codex see the picture; Copilot and Antigravity get only the text read from it. What each tool does and what waits for you is in [Assistants and Brainstead's tools](help:assistants).
